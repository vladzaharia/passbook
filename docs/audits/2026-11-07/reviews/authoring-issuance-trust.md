## Summary

Source-only backend trace; no checks or external calls. Preview, create, and update can use different pass-generation contexts and template versions. Resend retries do not inherently preserve their original recipient or attachment intent.

## Evidence and synthetic acceptance

- **Template version:** Preview resolves the requested `body.version`, or the registry’s active version, and returns that version’s asset URL (`src/worker/modules/templates/service.ts:221-230,263-270`; `src/worker/modules/templates/registry.ts:105-124`). Create resolves its optional version the same way, then builds and stores the resolved version (`src/worker/modules/passes/create.ts:78-100,108-118`). Update instead retains the pass’s stored version unless explicitly patched (`src/worker/modules/passes/service.ts:58-85`; `src/worker/modules/passes/publish.ts:87-105`). **UI impact [INFERENCE]:** editing a v1 pass with the active v2 schema can produce a PATCH validated/built against v1.

- **Preview versus issued package:** Preview supplies a platform identity, literal serial `preview`, fixed scan code and synthetic auth token (which it removes from returned JSON); it does not sign (`src/worker/modules/templates/build-check.ts:42-66`). It uses `manifest.sample` only when `input` is omitted; partial input is not merged with sample (`src/worker/modules/templates/service.ts:253-270`). Create uses the resolved signing identity, generated serial/token/scan code, org branding and the supplied input (`src/worker/modules/passes/create.ts:78-101`). Actual builds include org images, pass-specific image overrides and member-photo thumbnail (`src/worker/modules/passes/builder.ts:188-224`); preview returns template and preview-only assets only (`templates/service.ts:263-270`). **Synthetic, not executed:** with org logo and pass thumbnail, preview omits those assets; the issued package includes them. A partial `{}` preview input does not use sample values; omitted `input` does.

- **Resend intent:** Resend defaults omitted `to` to the current holder and omitted `attach` to `false` (`src/worker/modules/passes/service.ts:216-231`; `src/shared/contracts/passes.ts:235-238`). The queue stores the original `{to, attach}` (`src/worker/modules/delivery/service.ts:119-134`), but pass detail exposes delivery state/error—not those fields (`src/worker/modules/passes/detail.ts:186-195`). Given the UI Retry behavior reported by the parent, retrying with `{}` sends to the holder and omits the original `.pkpass`. Create always queues without an attachment (`src/worker/modules/passes/create.ts:179-184`); the only email attachment supported here is that `.pkpass` (`src/worker/modules/delivery/email.ts:110-128`).

- **Mode and delivery:** Create has no mode field. Admin session mode is Test only for exact `x-passbook-mode:test`; otherwise Live. API-key mode is fixed, and connection-created passes are forced Live (`src/shared/contracts/passes.ts:174-189`; `src/worker/platform/auth.ts:139-146`; `src/worker/modules/passes/create.ts:82-84`). Test email is captured rather than sent; delivery is asynchronous (`src/worker/modules/delivery/email.ts:87-96`; `delivery/service.ts:177-188`).

- **Validation/errors:** Missing binding targets are warnings, and runtime field/action bindings may no-op (`src/worker/modules/templates/package/manifest.ts:237-253`; `src/worker/modules/templates/package/analyze.ts:56-57`; `src/passkit/template/bindings.ts:46-59,78`). Build/input errors map to 422; stale `If-Match` to 412; exhausted publish retries to 409 (`src/worker/modules/passes/builder.ts:290-300`; `src/worker/modules/passes/publish.ts:87-90,226-270`). Create idempotency is optional.

**Baseline repeats, not novel:** omitted connection takeover defaults to takeover (`src/worker/modules/passes/connection-bind.ts:43-47`); create suppresses email-cap errors (`passes/create.ts:179-189`). Both are in `docs/audits/2026-11-07/reviews/03-ux-customer-business.md:29-33,77-80`.
