# Inbound partner acceptance scenarios — proposed, not executed

All fixtures must be local/in-memory: fake upstream, fake queue, fake signing/mail transport; no production bindings or real recipient delivery. These scenarios supplement local://inboundpartner1.md and are not verification claims.

1. **Mapped explicit clear:** Use a local template requiring a name and allowing an optional string message. Issue a connection-owned pass with a nonempty message. Apply a subsequent full source record containing `message: null` through configured mapping. Assert the old message is absent from persisted personalization and the built pass. Repeat after manually overriding that message; the override must remain. This separates explicit source clearing from omission in a partial update.
2. **Manual-lock prevalidation:** Use two schema-constrained fields. Manually override one required string; the upstream then returns a number for that locked field and a valid change for the second. Run the actual connection `applyIncoming`/pass publication seam, not a stubbed `applyConnectionRecord`. Assert the override remains, the unlocked field changes, and the run/pass does not acquire a record-validation error solely for the ignored field.
3. **Aggregate quota:** Configure HTTP JSON without a list endpoint, concurrency one and a small RPM limit. Bind several due references. Hold the first fake fetch open, start scheduled synchronization, then launch an admin synchronization using its distinct workflow ID. Record aggregate in-flight fetches and timestamps; also overlap a webhook invalidation or pass refresh. Assert shared connection admission keeps in-flight work at one and respects the declared aggregate rate. Per-execution counters alone do not establish this property.
4. **Dedupe ID validation:** Sign two valid push bodies for different refs using the same empty event ID; separately sign bodies with distinct IDs sharing the first 200 characters. Neither invalid-ID pair should silently turn a distinct record into an acknowledged duplicate: reject malformed/oversized identifiers before acceptance. Also demonstrate/document that omitted IDs and fresh timestamp signatures currently create different signature-derived IDs; senders need explicit stable IDs.
5. **Mapping repair/replay:** Accept a push or delta record whose mapping fails the template schema. Correct mapping without changing the source record. Resend the same event ID or use Sync now. A supported repair/replay operation should eventually apply the original record without requiring an artificial upstream update; it must not replay successful records or upgrade old revoked authorization. Until implemented, document that ordinary retry/Sync now is not such an operation.
6. **Invitation cap:** Seed the local org email counter at its 500/day limit, then create one connector pass with a valid distinct holder and auto-email enabled. Confirm creation succeeds but no email outbox row exists under current behavior. A release-ready import outcome must identify the suppressed invitation and provide explicit recovery, rather than reporting delivery success.
7. **Test and lifecycle boundary:** In an admin Test-mode context, probe an unsaved connection and assert no credential/pass persistence; observe fake upstream calls to establish that Test still uses the supplied real endpoint/credentials. Creating/syncing a connection currently issues live passes. Separately delete a connection and check retained pass state; void a missing source member and let the source return. Document and test the selected detach/revoke/reactivate policy, not an assumed automatic one.

Retain prior local acceptance for test-key/live connector isolation, durable webhook dispatch interruption, deferred publish conflicts, and generation/binding changes during publication. See the inherited audit cross-references in the standalone report.
